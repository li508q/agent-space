# AgentSpace delivery

Use `docs/product-brief.md`, `docs/PRD.md`, `CONTRIBUTING.md` and the current code. A change must serve direct writing, shared context, understandable decisions or recovery. Local task records in `.coordination/` may supply the current assignment; they do not replace the public contracts.

## Define a bounded change

Specify the user action, observed gap, exact resulting behavior, affected paths and completion check. Separate requirements from examples and engineering failure cases. Monthly reporting and project handoff are examples of composable work, not built-in workflow engines.

Give each contributor an objective, inputs, owned paths, exclusions, checks and stopping point. Use disjoint edits and one native GUI runner. Independent reviewers inspect original requirements, code and raw results before reading implementation conclusions.

## Implement and verify

Preserve shared identity, versions, sources, permissions, direct human saves and proposal-based agent changes. Reuse the Core and trusted adapters. Keep personal data and generated artifacts outside public source.

Match each claim to inspected code or an actual result. A passing unit test does not establish native behavior; a tool response does not establish host understanding; an accepted proposal does not certify knowledge. Retain failures and their exact scope in private evidence.

Use the relevant interface skills for UI work. Keep all five languages consistent and verify changed controls in the real application. Use isolated fixtures and the shared memory clipboard device for native tests.

## Publish

Run the checks in `docs/TESTING.md` that cover the change, plus source, formatting and documentation gates. Review the complete diff, stage only owned files, and publish only within the assigned repository scope. Verify the exact commit's CI result.

Public documentation describes the product, its contracts and operating limits. Keep task chronology, repair narratives, private paths and session coordination in private records. Do not expand a focused change into another product area.

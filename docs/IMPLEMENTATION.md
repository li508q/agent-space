## Shared boundaries

`src/contracts/schema.ts` contains strict request shapes, IDs, authored field labels, typed values, current/pinned refs, create/update proposals, bound read pages, review binding, tool names and locale names. `src/contracts/errors.ts` defines machine-readable failures. Core services must recheck authorization, revision, policy, schema version and byte budgets; a parsed request alone is not permission.

Use typed `Result<T>` envelopes across IPC/tools. Add response types before adapters consume them. A core call receives an adapter-supplied principal, never an actor from request JSON. Only the core mutates authority. File dialogs and import/export destination selection belong to the desktop adapter; pure backup/export validation belongs to the core. No renderer imports of main/core/platform modules.

| Owner role              | Owned paths                                                                 | Contract with other owners                                                                     |
| ----------------------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Core/storage            | `src/core/`, `tests/core/`, `tests/fixtures/`                               | Versioned object/proposal/receipt API, typed result/error, deterministic test fixture builders |
| Agent adapter           | `src/adapters/`, `tests/protocol/`                                          | Shared read/propose services, configured principal and grant; no human commands                |
| Desktop boundary/build  | `src/desktop/`, `scripts/`, build config, `tests/desktop/` boundary harness | Named preload methods and lifecycle events; active-space generation and dialog-owned paths     |
| Interface/localization  | `src/renderer/`, renderer-only assets, `tests/ui/`                          | Snapshot/draft/review state via preload; no storage or permission implementation               |
| Integration/coordinator | Shared contracts/config, cross-boundary E2E, docs/evidence integration      | Resolves contract changes before dependent work and owns phase transitions/Git                 |

These are possible work assignments, not automatically created sessions. One owner must control shared contracts/config at a time. Owners may work in parallel only after the relevant interface is frozen by the coordinator; neither adapters nor UI invent private mutation semantics.

Folder recognition is a replaceable import Profile, anchored to SC-01 rather than a mandatory storage layout. Default bounds: depth 12, 1,000 visited files, 50 MiB selected text and the managed per-object size limit; skip symlinks and `.git`/dependency/build directories, reporting skips. The preview can map ordinary text to independent notes and confirmed project groups; an automatically maintained knowledge folder does not certify its contents as reviewed knowledge. Persist the confirmed import manifest and per-item operation keys: retry the same item/source digest once, preserve separate origins for different files, and require a new preview for changed sources. Import commits are per item with explicit partial outcomes, not a claimed atomic whole-folder migration. There is no watcher, dual master, automatic source overwrite or universal migration platform.

After phase 4, stop for integration review. Phase 5 performs independent acceptance, failure correction and packaged-app verification; phase 6 finishes five-language publication and reviewed GitHub delivery. Product tests accompany every slice, not only phase 5.

## Verification and commands

The commands currently present are deliberately limited:

```sh
npm ci
npm run check
npm run format:check
```

`check` typechecks/lints the contracts and runs six boundary-schema tests. It is not an application check. Electron's npm package can download its pinned binary on first invocation; dependency installation is not an offline product-start guarantee. Probes remain local in the ignored coordination directory and are summarized in [TESTING.md](TESTING.md).

Phase 3 adds actual `build`, `dev`, protocol-test and desktop-test scripts only when their entries exist. Phase 4 adds core backup/import/export tests. Phase 5 adds packaging and packaged-path smoke commands. Do not retain scripts pointing to nonexistent files or describe development commands as published installation packages.

Before each handoff, report changed paths, observed evidence, failures/limits and the next bounded assignment. The root coordinator owns shared-document integration, commits and push; no slice publishes a release.

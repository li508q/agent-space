Status: intended first-release behavior. Native interaction, accessibility, and five-language layout verification remain pending. Scope and acceptance requirements are defined in [PRD.md](PRD.md).

## Workspace and navigation

Use a document workspace with four destinations: **Continue working**, **Projects**, **Library**, and **Review**. Search and **New note** remain reachable from every destination. The space name stays visible; an example space carries a persistent **Example space** label. Do not require a model account to create, edit, search, or recover material.

Continue working shows pinned/recent material and an entry to unresolved proposals. Reopening a space restores the last object, selection, and scroll position. Project pages show the person's goal, state, continuation reference, and linked material. Library filters content, records, and reusable assets without creating duplicate objects. Review's count means unresolved proposals, including conflicts; unread is a separate indicator.

```text
┌ Space name ▾    Back / Forward       Search space ⌘K       New note ┐
├────────────────┬──────────────────┬────────────────────────────────┤
│ Continue working│ Project name     │ Project / Retry policy         │
│ Projects        │ Goal: …          │ Retry policy                   │
│ Library         │                  │ Saved 14:32    History   Details│
│ Review       2  │ Material         │ Sources 1 · Relations 2        │
│                 │ [Filter]         │────────────────────────────────│
│ Pinned projects │ Retry policy  ◀  │                                │
│ Project name    │ Measurement note │ Comfortable, editable Markdown │
│                 │ Reference records│                                │
│                 │                  │                                │
├────────────────┴──────────────────┴────────────────────────────────┤
│ Show exceptional state here only: search has not caught up. Details│
└────────────────────────────────────────────────────────────────────┘
```

**Details** opens properties, relationships, sources, and asset references for the selected object. It does not become a permanent fourth column at the expense of writing width. History and source navigation preserve a return location, including the review's selected change and scroll position. Use sheets/dialogs for bounded tasks such as choosing files; use normal navigation for reading and editing.

Field identity and display labels are separate. The system maintains stable internal keys; people name fields in their own language and are never required to enter ASCII column names. Renaming a label does not replace a field or break its references. User-authored labels retain their language when the interface locale changes.

Project membership and ordinary relationships follow stable object identity and display the target's current name/state. Source evidence pins a revision and location. An asset-use reference can explicitly pin a version; show that choice rather than silently freezing ordinary relationships at selection time.

Notes, working documents, and knowledge material use the same content identity with an optional role. Project state belongs to the project. Record fields distinguish **Not set**, empty text, and `0`; **Clear value** unsets a field rather than inventing a numeric zero. Knowledge review is a separate human action in Details, associated with the checked content version; later body/property/source-link changes show **Needs review**. Saving, reading, or applying a proposal never marks knowledge reviewed or certifies it as true.

The Markdown preview must not execute embedded scripts or active content. Opening links requires a person’s action. Background refresh must not replace a dirty editor buffer; offer the new persisted version alongside the person's retained input.

### Save feedback

The status beside the title describes the visible editor buffer, not merely the last completed request.

| State                               | Visible feedback                                         | Available next step                                                           |
| ----------------------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Changed, not submitted              | **Unsaved changes**                                      | Keep typing; Save now                                                         |
| Save in flight                      | **Saving…**                                              | Keep typing; queue newer edits without losing their generation                |
| Visible buffer durably saved        | **Saved**, with inspectable time                         | Continue or navigate                                                          |
| Persistence failed                  | **Not saved — [specific cause]**                         | Retry; copy/export input; remain in editor                                    |
| Result not yet known                | **Checking save result…**                                | Query the original operation; do not create a second write                    |
| Current revision advanced elsewhere | **Content changed elsewhere. Your edits are kept here.** | Inspect current content; keep/copy the draft; no automatic overwrite          |
| Recovery draft durably retained     | Secondary **Recovery draft kept**                        | Resume it or discard explicitly; this does not mean current content was saved |

An earlier successful save cannot label newer input Saved. Serialize saves per object and preserve operation identity when checking/retrying an uncertain result. Do not promise a recovery draft was kept until retention succeeds. If retention also fails, keep the in-memory input and explain how to copy it before closing. Save errors persist near the title; a transient toast is insufficient.

## Preparing context

**Prepare context** is available from a project or selected material. It opens a small, editable selection: task description (optional), project/material references, pinned revisions, and an entry for further discovery. Users can remove or add references without changing the source objects.

Context delivery records the exact revisions actually read. It does not turn project membership or ordinary object links into historical-version links.

| Action                      | Outcome and feedback                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Search/filter material      | Show the executed project/type/date scope, loaded results, and a reachable next page. Preserve the query and selection when opening a result. Distinguish no matches from unavailable sources or an incomplete index.                                                                                                                                                                                                                                               |
| Follow a typed relationship | Show its direction and target. State when a result limit stops expansion; offer continuation rather than implying completeness.                                                                                                                                                                                                                                                                                                                                     |
| **Copy context entry**      | Copy references and navigation instructions, not an undisclosed full-space dump. Confirm what was copied; missing/unreadable references remain explicit.                                                                                                                                                                                                                                                                                                            |
| **Export selected text**    | Preview the actual included text and source revisions before writing it. Report exclusions and the chosen destination; return to the same selection.                                                                                                                                                                                                                                                                                                                |
| **Set up agent access**     | Show the configured space, readable scope, proposal-only mutation capability, and a real built entry point. Object-scoped access can propose revisions to its existing target only. Only space-scoped access offers a separately enabled **Propose new notes/records** capability; space scope alone does not enable it. Neither grant permits automatic creation or human-only acceptance. Configuration failures retain settings and explain how to correct them. |

Agent access reports **Entry enabled** and **Last tool call…** when those observations exist. It must not infer “thinking,” “finished,” or a live connection from configuration alone. Delivered-material details show actual tool-supplied references, versions, and known limits; they do not prove the model read or understood everything. Client-provided names are declarations, not verified model identity.

## Proposal review

**Each proposal concerns exactly one object: an existing object to revise, or a new note/record proposed for creation.** It may include that object's body, properties, and relationships. Linked sources/assets are not additional mutation targets. Each proposal has its own outcome; no cross-object Apply all or atomic bundle is implied.

```text
┌ Review / Narrow retry conditions                    Pending review ┐
│ Client A · Submitted 14:36                 Current content unchanged│
├─────────────────────┬───────────────────────────────────────────────┤
│ Target              │ Declared purpose                              │
│ Retry policy        │ Limit retries using the measurement results.  │
│                     │                                               │
│ Changes in object   │ Original at submission  Proposed content      │
│ Body                │ ──────────────────────  ───────────────────── │
│ Property: status    │ - Retry every failure   + Retry recoverable…  │
│ Relation: Uses asset│                                               │
│                     │ Property: status — Draft → Ready              │
│ Source              │ Relation: add Uses asset → Request adapter    │
│ Measurement note v3 │                                               │
│ Results [Open]      │ Agent-provided reason: …                      │
├─────────────────────┴───────────────────────────────────────────────┤
│ Reject proposal        Open current object to edit     Apply proposal│
└─────────────────────────────────────────────────────────────────────┘
```

Show declared purpose, actual differences, agent-provided reason, and cited sources before technical receipts. The diff includes every changed body section, property, and relationship. Use explicit added/deleted labels and symbols as well as color. Keep the target title prominent; IDs, hashes, base revision, and operation details remain inspectable in Details.

A creation proposal uses this same review surface with **Proposed new note** or **Proposed new record** and **Not created yet**. Show the proposed content and fields as additions, without submission-time original/current-object panes or an accepted base revision. Until human acceptance, it appears in Review, not as current material or a record row. Replace Apply with **Create note** / **Create record**, and omit **Open current object to edit**. An empty proposed title uses the localized placeholder.

| Action/state                                      | Preconditions and result                                                                                                                                                                                                                       | Failure, next action, and return                                                                                                                                                                                                                                                                                              |
| ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Open proposal                                     | Retain its immutable proposed content, purpose, sources, and outcome, plus the original/base for revisions only. Mark this proposal read only after opening it.                                                                                | Read/unread never resolves it. Returning to the list restores its filter, selected row, and scroll.                                                                                                                                                                                                                           |
| **Apply proposal** (existing object)              | Unresolved proposal, compatible current revision/policy, and no unresolved dirty buffer for that target. Recheck at submission, then apply the one-object change once.                                                                         | Show progress on the action. Unknown result is checked under the same identity. Confirm **Proposal applied**, expose the result/history, and update the unresolved count only after a definite outcome.                                                                                                                       |
| **Create note** / **Create record** (new object)  | The creation proposal has no accepted base. Recheck configured creation permission, applicable schema, references, and identity constraints; human acceptance creates one current object with stable identity and its first accepted revision. | Confirm **Note created** / **Record created**, with **Open created note/record** and history. Policy/schema/reference failure or an identity collision keeps the proposal and explains the cause; never convert creation into an overwrite. | **Reject proposal**                               | Pending or conflicted proposal. Do not invent evidence or claim that a text merge resolves factual disagreement.                                                                                                                                                                                                 |

The first release uses the explicit direct-edit path above rather than an ambiguous **Revise proposal** action. For a new-object proposal, offer copying its text/values into the existing human New note/Add record flow; clearly identify the result as a separate human copy and leave the original proposal unresolved. If a separate proposal-draft editor is introduced later, it must preserve the original and attribute the final human revision. Copying proposed text or values remains available without applying them.

| Reading             | Unread / Read, independent of processing                                                                   |
| Knowledge review    | Not reviewed / Reviewed / Needs review, independent of reading and applying                                |

## History and conditional undo

History shows accepted object versions and durable proposal outcomes with actor/source, time, and differences. Creation history shows the created object and its first revision, without a fictitious prior version. Selecting a version opens an explicitly historical, read-only view. Leaving it restores the current editor/review location without substituting old content into a dirty buffer.

**Preview undo** names the change and displays the whole object's body, properties, and relationships that would be restored. First-release undo is conservative: the current revision must still be the revision produced by that change. Recheck that condition when committing; matching text alone is insufficient. For a creation event there is no prior content: use an explicit **Undo creation** preview explaining that the created object will be archived while identity and history remain. Do not display a fictitious previous version or imply permanent deletion. Later edits block this action under the same guard.

- Compatible: **Undo change** creates a new saved version and a durable history entry. Show the resulting object and highlight the changed area.
- Later revision exists, including a change made while the preview was open: stop. Show **Later changes prevent this undo. Current content has not been replaced.** Offer **View previous version**, copy its text/field values, and **Create note from this version**. The new note has a new identity and a source reference; non-document versions become a readable field/reference snapshot in the note. It does not restore the original object or change existing records.
- Failed or uncertain result: retain the preview and check the same operation before reporting success or offering retry. Never fall back to restoring the whole space.

Editor Undo/Redo affects editing input through normal platform commands. History's **Undo change** is a separate guarded operation. Backup restore is a separate space-level action.

## Keyboard, composition, focus, and layout

- Expose commands in menus as well as shortcuts: New note (⌘N), Search space (⌘K), Save (⌘S), Find in document (⌘F), Settings (⌘,), and standard editor Undo/Redo. Use platform equivalents on other systems. Do not bind a global shortcut that can accidentally apply a proposal while typing.
- Tab follows navigation → list → content/actions; all primary operations work without dragging or hover. Tab can leave the editor. If indentation captures Tab, provide a discoverable keyboard exit. List arrows change selection; Enter opens; Escape closes a transient surface and returns focus, without discarding unsaved content.
- During IME composition, do not intercept Enter/Escape as navigation, submit, or dismissal, and do not save unfinished composition as final text. Schedule autosave after composition ends. Defer navigation that would destroy the composing buffer. Verify Chinese, Japanese, and Korean composition with native input methods.
- Opening a route focuses its heading or main content, not an unrelated action. Returning from a source restores the review trigger and reading position. A source-details panel has a named close control; closing restores its trigger. Modal focus stays inside until closed.
- Use visible focus on every control, sufficient contrast, and one appropriate contextual status announcement. Do not announce every keystroke or competing badge count. Fixed bars reserve content space and must not obscure focused controls.
- At ≥1440 CSS px, allow navigation ≈208, list ≈232, flexible content, and optional details ≈288. At 1100–1439, Details replaces the list rather than crushing the editor. Below 1100, use a collapsible navigation and list/detail route with Back. Preserve selection across these changes.
- Keep prose around 60–75 Latin characters per line; verify CJK reading width separately. Narrow review uses stacked diff sections. Critical actions and states stay complete; action groups may wrap. Unpredictable titles can truncate only with keyboard-accessible full-text disclosure.
- Verify 1100×720 and 1440×900, narrow windows, and 200% text zoom. Content must reflow; tables may scroll within their own named region, while controls remain reachable. Honor reduced motion; use short state transitions, without decorative entrances or layout-shifting feedback.

## Interaction references

The desktop layout uses the limited hierarchy and collapsible-navigation guidance in [Apple Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars.md). Predictable undo outcomes follow [Apple Undo and redo](https://developer.apple.com/design/human-interface-guidelines/undo-and-redo.md). Status feedback and unobscured keyboard focus follow [W3C Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) and [W3C Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html). Proposal and recovery behavior is defined by the PRD; these references do not imply a general automatic merge or truth-verification capability.

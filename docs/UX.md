## Workspace and navigation

Use a document workspace with four destinations: **Continue working**, **Projects**, **Library**, and **Review**. Search and **New note** remain reachable from every destination. The space name stays visible; an example space carries a persistent **Example space** label. Do not require a model account to create, edit, search, or recover material.

Continue working shows retained recovery drafts, at most ten recent objects from this space instance, and **View recent changes** into the existing Activity view. It does not query or copy the complete material directory. Recent positions store only IDs/times; at most two existing current reads run concurrently to check their live summaries. Missing entries can be removed from recent positions without deleting material; archive remains visible, transient failures expose retry, and unavailable position storage is distinct from empty results. A restored/new instance starts with its own recent positions. Reopening remembers the last object's identity; it does not persist text selection or the source-reading stack.

Library is the complete bounded browsing entry. Its **Review status** select defaults to all and offers **Never reviewed**, **Current version reviewed**, and **Changed since review**. Never reviewed is neutral information, not a warning or a task count. Search/type/lifecycle, the review filter and New material use one ordinary list-scroll flow in every layout so the short viewport retains a complete focused row. State replaces the existing date metadata line rather than adding row height. Project pages retain their bounded goal excerpt, continuation, linked material and direct assets. Review's count still means unresolved proposals, including conflicts; unread remains separate. Global Back/Forward history and pinned-project navigation are not implemented.

Details **Version review** shows the current saved head H and highest human-reviewed revision R, or explicitly no reviewed version. This metadata is separate from the editor's base, dirty buffer, generations and caret. Same-H new-R reads update it without replacing input. Marking reviewed requires fresh current metadata, clean/noncomposing/unlocked input and base=H, using that exact pin. Saving, reviewing and decisions synchronously supersede old query/current-read/MRU epochs for data, error and loading. Re-fetch current results after a mutation; an old write/review receipt never becomes current-head metadata. Historical reader contents and the Activity fixed-pin title map remain exact-version presentation only.

┌ Space name ▾                    Search space ⌘K   New note   ⚙   ┐
├────────────────┬──────────────────┬────────────────────────────────┤
│ Continue working│ Project name     │ Project / Retry policy         │

│ Library         │                  │ Saved 14:32    History   Details│
│ Review       2  │ Material         │ Sources 1 · Relations 2        │
│                 │ [Filter]         │────────────────────────────────│
│                 │ Retry policy  ◀  │                                │
│                 │ Measurement note │ Comfortable, editable Markdown │
│                 │ Reference records│                                │
│                 │                  │                                │
├────────────────┴──────────────────┴────────────────────────────────┤

**Details** opens properties, relationships, sources, and asset references for the selected object. It does not become a permanent fourth column at the expense of writing width. History and source navigation preserve a return location, including the review's selected change and scroll position. Use sheets/dialogs for bounded tasks such as choosing files; use normal navigation for reading and editing.

Field identity and display labels are separate. The system maintains stable internal keys; people name fields in their own language and are never required to enter ASCII column names. Renaming a label does not replace a field or break its references. User-authored labels retain their language when the interface locale changes.

Project membership and ordinary relationships follow stable object identity and display the target's current name/state. Source evidence pins a revision and location. An asset-use reference can explicitly pin a version; show that choice rather than silently freezing ordinary relationships at selection time.

Notes, working documents, and knowledge material use the same content identity with an optional role. Project state belongs to the project. Record fields distinguish **Not set**, empty text, and `0`; **Clear value** unsets a field rather than inventing a numeric zero. Knowledge review is a separate human action in Details, associated with the checked content version; later body/property/source-link changes show **Needs review**. Saving, reading, or applying a proposal never marks knowledge reviewed or certifies it as true.

The Markdown preview must not execute embedded scripts or active content. Opening links requires a person’s action. Background refresh must not replace a dirty editor buffer; offer the new persisted version alongside the person's retained input.

Field and relationship dialogs retain their input during composition, ignore composition Escape dismissal, and return focus to their trigger. Main-window close is cancelled while a dialog requires a decision. They never mark unapplied form values as saved. After application, 800 ms autosave, 250 ms recovery retention, generation checks, same-key uncertain-result recovery, and the close lock remain the shared editor behavior. The record table uses semantic row/column headers and confines horizontal overflow to its named table region; surrounding navigation and actions reflow.

**Edit current original**, from a reader, reads the same object's current revision through the existing protected editor transition. Historical K1 stays read-only; editing current K2 saves K3 on the same ID. It never calls the separate **Create note from this version** action. An existing editor for that ID is reused: unsaved old-base input remains labeled as such, and a newer current version is shown as a conflict rather than substituted into the buffer. Archived or unavailable current objects leave the historical reader intact with a specific next step.

**Return to reading** restores the cited reader and its edit-action focus. Finishing the reading stack restores the calling project/document, review or table; replacing an editor first saves or confirms a recovery draft. A retained original draft is reopened as that draft. Returning to a project reloads its bounded material pages when needed for the prior trigger. A cancelled opening keeps the existing reader and input; obsolete replies cannot change it. Position restoration is bound to the route, editor identity and input generation, and stops if later navigation, writing or a project-view change supersedes it. These return checkpoints are in-session navigation, not a persisted global Back/Forward history.

### Save feedback

The status beside the title describes the visible editor buffer, not merely the last completed request.

| State                               | Visible feedback                                         | Available next step                                                           |
| ----------------------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Changed, not submitted              | **Unsaved changes**                                      | Keep typing; Save now                                                         |
| Save in flight                      | **Saving…**                                              | Keep typing; queue newer edits without losing their generation                |
| Visible buffer durably saved        | **Saved**, with inspectable time                         | Continue or navigate                                                          |
| Persistence failed                  | **Not saved — [specific cause]**                         | Retry; copy/export input; remain in editor                                    |
| Result not yet known                | **Checking save result…**                                | Query the original operation; do not create a second write                    |
| Current revision advanced elsewhere | **Content changed elsewhere. Your edits are kept here.** | Inspect current content; keep/copy the draft; no automatic overwrite          |
| Recovery draft durably retained     | Secondary **Recovery draft kept**                        | Resume it or discard explicitly; this does not mean current content was saved |

An earlier successful save cannot label newer input Saved. Serialize saves per object and preserve operation identity when checking/retrying an uncertain result. Do not promise a recovery draft was kept until retention succeeds. If retention also fails, keep the in-memory input and explain how to copy it before closing. Save errors persist near the title; a transient toast is insufficient.

An asynchronous action that replaces the editor first waits for composition, pauses writing, and confirms the old buffer is saved or durably retained. Keep writing paused through the opening/creation reply and installation, with a visible **Opening material** or **Creating material** state. A cancelled or failed read keeps the old editor. Every installation invalidates unrelated pending editor reads; a remembered startup read cannot replace a later user choice. Navigation, space switching, and native close hold independent locks, and a new editor inherits any lock still owned by an unfinished close. Switching spaces keeps the old editor paused until its old binding is unmounted. A late reply must not release another operation's lock. Retry after a retention failure follows the same guarded path.

## Preparing context

Prepare context by finding material, reading its sources and copying one explicit saved version. **Copy saved context** is beside the saved state and in the read-only source reader. It copies the space and instance identity, object ID, revision, digest, title, typed fields and relationships, plus either the saved body or the editor's selected body text. The clipboard payload names its one-object scope and distinguishes a body selection from the complete body. It does not recursively include linked bodies.

Disable this action for dirty, composing or locked editor input; offer **Save now** first. **Copy edits** remains a separate rescue action for unsaved text and makes no saved-version claim. Exact reads and prepared tool results retain the versions actually supplied; project membership and ordinary links still follow object identity.

Agent access reports **Entry enabled** and **Last tool call…** when those observations exist. It must not infer “thinking,” “finished,” or a live connection from configuration alone. Prepared-material details show the references, versions and known limits prepared for a tool return; they do not prove host receipt or model understanding. Client-provided names are declarations, not verified model identity.

## Durable change discovery

The existing **Activity** dialog defaults to **Actual changes**; **Prepared context** is separate. Event rows name the recorded action, time and actor. A proposal-created event remains a creation event even if its proposal is now applied; review shows the current proposal status separately. Review, access, archive and rejection events do not imply a changed body. Version links are pinned to the event's after revision. Unknown actions retain their recorded code.

Recent changes use fixed, descending numerical windows of at most 50 authority sequences. Prepared context uses independent activity-sequence windows before filtering; an empty window can still have earlier records. Refresh starts a new window. Keep successful pages on failure, retry the same boundary and label counts as loaded records. A tab, binding or request-generation change invalidates old replies. The dialog is closed while reading a source; returning restores its tab, pages, scroll and trigger without a hidden modal focus trap.

Review offers **Pending** (pending/conflicted) and **Processed** (applied/rejected), with independent per-status ID cursors, loading, errors and retry. Do not present loaded pages as a global total or newest-first snapshot. List refresh and status transitions do not clear the selected review. Reading a source, editing its current original and returning preserve that selection even when it is no longer in the current loaded group.

Applied proposals expose their durable result revision separately from current content after restart. Keep the original base-to-proposed difference, declared reason and exact source pins. A rejected creation has no accepted object or result link; no human rejection reason is fabricated. A real decision synchronously invalidates older detail reads, including their error/loading/seen callbacks; statusVersion and current-object revision never regress within that detail.

## Proposal review

**Each proposal concerns exactly one object: an existing object to revise, or a new note/record proposed for creation.** It may include that object's body, properties, and relationships. Linked sources/assets are not additional mutation targets. Each proposal has its own outcome; no cross-object Apply all or atomic bundle is implied.

│ Client A · Submitted 14:36                 Current content unchanged│
├─────────────────────┬───────────────────────────────────────────────┤
│ Target              │ Declared purpose                              │

Use explicit added/deleted labels and symbols as well as color. Keep the target title prominent; IDs, hashes, base revision, and operation details remain inspectable in Details.

A creation proposal uses this same review surface with **Proposed new note** or **Proposed new record** and **Not created yet**. ## History and conditional undo

History shows accepted object versions and durable proposal outcomes with actor/source, time, and differences. Creation history shows the created object and its first revision, without a fictitious prior version. Selecting a version opens an explicitly historical, read-only view. Leaving it restores the current editor/review location without substituting old content into a dirty buffer.

**Preview undo** names the change and displays the whole object's body, properties, and relationships that would be restored. First-release undo is conservative: the current revision must still be the revision produced by that change. Recheck that condition when committing; matching text alone is insufficient. For a creation event there is no prior content: use an explicit **Undo creation** preview explaining that the created object will be archived while identity and history remain. Do not display a fictitious previous version or imply permanent deletion. Later edits block this action under the same guard.

- Compatible: **Undo change** creates a new saved version and a durable history entry. Show the resulting object and highlight the changed area.
- Later revision exists, including a change made while the preview was open: stop. Show **Later changes prevent this undo. Current content has not been replaced.** Offer **View previous version**, copy its text/field values, and **Create note from this version**. The new note has a new identity and a source reference; non-document versions become a readable field/reference snapshot in the note. It does not restore the original object or change existing records.
- Failed or uncertain result: retain the preview and check the same operation before reporting success or offering retry. Never fall back to restoring the whole space.

Editor Undo/Redo affects editing input through normal platform commands. History's **Undo change** is a separate guarded operation. Backup restore is a separate space-level action.

**Accepted explanation** on a version reads the original declared purpose/reason and exact evidence pins for that accepted change. A directly saved human version has no such declaration; show neutral explanatory text. A source may now have a newer head, but the evidence link opens the cited revision. Missing evidence and bounded continuation remain visible. Acceptance and saving do not certify truth. Reading keeps the caller mounted; entering an editor from the reader uses the protected return checkpoint described above.

An external asset location change shows the old/new location. It cannot use generic history undo: direct the person to **Choose a new location**, preserving the asset's identity and history.

Referenced external assets are references unless bytes were actually included.                                                                                                                                                                                                                                       |
| **Restore backup**                                         | Validate it before use, choose a new location, then open the checked restored space. Preserve the promised object/version references.                                                                                                                                                                                                                                                                                                               | Invalid/incomplete backups stay unopened with actionable errors. Never clear or overwrite the current space first. Dialogs use visible labels, a specific primary action, and Cancel. On close, focus returns to their trigger. Unfinished import/backup work reports only actual progress; it does not create an agent activity simulation.

### Local task details

- **Import** lives in the space menu. Choose files/folder and a replaceable interpretation profile. Load every bounded preview page before enabling confirmation; show loaded entries, selected items, root count, scan limits and exclusions. Suggestions are editable: keep independent, use an existing project, or create/map a suggested group. External references require an explicit choice. Grouping applies only to new copies: the same source/version reuses its original object and existing relationships. Confirmed results show relative paths and each actual committed/reused/skipped/failed/blocked state. Open a reused item through its original reference, never the unused planned target ID. Result pagination states the loaded/total range and refresh preserves expanded pages. Pause, reset selected failures, and resume are distinct actions; source reauthorization can return a replacement preview which requires fresh approval. Leaving modified preview controls asks whether to keep editing or discard those controls; originals are never changed.
- **Back up, export and restore** is reachable from the space menu; restore also exists on welcome. Full-history backup and readable current export have separate actions and exclusions. Both use a newly selected destination. Progress names only reported stages, processed counts and bytes; omit percentage when total is unknown. Completion requires a checked artifact receipt. Preserve the original operation ID and transfer handle on an uncertain reply; query/replay that artifact request instead of relying on the Core mutation ledger. Restoring creates and verifies a new space before a separate **Open restored space** action. The open uses the normal dirty-buffer/composition/space guard. An open failure does not erase the successful restore result.
- **Archive** in Details checks the current revision and affects one object. Library/Projects offer active/archived/all filters, defaulting to active. Archived objects are read-only. **Restore material** reactivates its current content, without restoring an older body or cascading to shared assets. External asset **Choose a new location** previews old/new labels before confirmation and preserves identity/history; no path is edited directly in the renderer.
- **Drafts from another installation** is in Continue working. Read the original first. **Copy original draft content** uses the native clipboard independently of draft retention, including when no new draft can be written. Its success says that no retained draft was created. **Keep a new recovery draft** copies to a fresh identity in this installation; only a retained receipt enables Resume. Original drafts stay unchanged and stale-base conflict checks still apply. The ordinary current-installation draft list remains separate.
- **Incoming links** in Details and asset where-used use one-level bounded relationship expansion, rather than fetching every object's body. Show loaded edges, missing references and reached limits. An incoming owner link opens the exact owner revision; a pinned target names its referenced version, including when it differs from the viewed head. Continuation does not imply an unrestricted or complete graph.

Unresolved local commands retain their original keys and controls; dialogs cannot dismiss an unknown mutation. Native close is cancelled while a dialog requires a decision. Local file transfers with known running handles may continue after their dialog closes; reopening shows the same in-process handles, without claiming restart persistence of that view.

## Keyboard, composition, focus, and layout

- Expose commands in menus as well as shortcuts: New note (⌘N), Search space (⌘K), Save (⌘S), Find in document (⌘F), Settings (⌘,), and standard editor Undo/Redo. Use platform equivalents on other systems. Do not bind a global shortcut that can accidentally apply a proposal while typing.
- Tab follows navigation → list → content/actions; all primary operations work without dragging or hover. Tab can leave the editor. If indentation captures Tab, provide a discoverable keyboard exit. List arrows change selection; Enter opens; Escape closes a transient surface and returns focus, without discarding unsaved content.
- During IME composition, do not intercept Enter/Escape as navigation, submit, or dismissal, and do not save unfinished composition as final text. Schedule autosave after composition ends. Defer navigation that would destroy the composing buffer. Verify Chinese, Japanese, and Korean composition with native input methods.
- Opening a route focuses its heading or main content, not an unrelated action. Returning from a source restores the review trigger and reading position. A source-details panel has a named close control; closing restores its trigger. Modal focus stays inside until closed.
- Use visible focus on every control, sufficient contrast, and one appropriate contextual status announcement. Do not announce every keystroke or competing badge count. Fixed bars reserve content space and must not obscure focused controls.
- At ≥1440 CSS px, allow navigation ≈208, list ≈232, flexible content, and optional details ≈288. At 1100–1439, Details replaces the list rather than crushing the editor. Below 1100, use a collapsible navigation and list/detail route with Back. Preserve selection across these changes.
- Keep prose around 60–75 Latin characters per line; verify CJK reading width separately. Narrow review uses stacked diff sections. Critical actions and states stay complete; action groups may wrap. Unpredictable titles can truncate only with keyboard-accessible full-text disclosure.
- Verify 1100×720 and 1440×900, narrow windows, and 200% text zoom. Content must reflow; tables may scroll within their own named region, while controls remain reachable. Honor reduced motion; use short state transitions, without decorative entrances or layout-shifting feedback.

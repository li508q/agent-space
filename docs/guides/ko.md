# AgentSpace 사용 안내

[English](en.md) · [简体中文](zh-CN.md) · [日本語](ja.md) · [한국어](ko.md) · [Español](es.md)

AgentSpace는 글, 프로젝트 자료, 에이전트 제안을 하나의 로컬 스페이스에서 관리합니다. 모델 계정 없이도 자료를 읽고 편집하고 정리하며 복구할 수 있습니다.

## 스페이스 만들기와 열기

새 로컬 폴더에는 **스페이스 만들기**, 기존 AgentSpace 폴더에는 **스페이스 열기**를 사용하세요. **예제 스페이스 열기**에서는 내 자료와 따로 저장된 예제를 사용해 볼 수 있습니다. 현재 스페이스는 상단에 표시됩니다.

앱과 스페이스는 별개입니다. 앱을 옮겨도 데이터는 이동하지 않습니다. 사용할 위치에 앱을 두고 그곳에서 연 뒤 에이전트 접근 권한을 만드세요. 나중에 앱을 옮기면 에이전트를 사용하는 앱의 MCP 구성에서 실행 파일 경로를 수정하고 다시 연결하세요.

**설정**에서 인터페이스 언어와 글자 크기를 선택합니다. 언어를 바꿔도 직접 작성한 제목, 본문, 필드 이름은 번역되지 않습니다.

## 작업 이어가기와 자료 찾기

**작업 이어가기**에는 복구용 초안, 이 스페이스 인스턴스의 최근 자료 최대 10개, **최근 변경 보기**가 있습니다. 최근 목록은 같은 자료를 가리키며 문서를 복제하지 않습니다. 사용할 수 없는 항목을 목록에서 제거해도 자료는 삭제되지 않습니다. 일시 오류는 재시도할 수 있고, 복원된 인스턴스는 자체 목록을 사용합니다.

**라이브러리**에서 저장된 자료를 탐색하고 검색·필터링하거나 **새 자료**를 만드세요. 최근 작업이 없어도 스페이스에 자료가 있을 수 있습니다. 로드된 개수와 페이지 결과는 확인한 범위를 나타내므로 필요한 경우 더 불러오세요.

## 기존 자료 가져오기

작업 이어가기, 스페이스 메뉴 또는 필터가 없는 빈 라이브러리에서 **기존 자료 가져오기**를 엽니다.

1. 파일이나 폴더를 선택합니다.
2. 미리보기에서 텍스트 사본, 프로젝트 묶음, 외부 참조, 제외 항목과 스캔 제한을 확인합니다.
3. 선택을 확정한 뒤 각 항목의 결과를 확인합니다.

유효한 UTF-8 Markdown과 일반 텍스트는 출처 정보를 가진 편집 가능한 관리 사본이 됩니다. 원본 파일은 그대로 유지됩니다. 저장소와 다른 형식은 외부 참조로 명시적으로 선택할 수 있으며 내용은 복사·실행·동기화하지 않습니다. 선택 사항인 **지식, 프로젝트 및 저장소** 프로필은 프로젝트 묶음과 저장소 참조를 제안합니다.

제한된 미리보기는 보고된 스캔 범위만 다룹니다. 미리보기 이후 원본이 바뀌면 다시 확인해야 합니다. 항목별로 저장하므로 일부 실패해도 성공한 자료는 남습니다. 재시도나 같은 원본 버전의 재가져오기는 기존 객체를 재사용하고 이후 직접 편집한 내용과 현재 관계를 보존합니다. 새 묶음 설정은 새 사본에 적용됩니다. 재사용 자료의 관계를 바꾸려면 직접 편집하세요. 다른 원본 버전은 별도 사본이 됩니다.

백그라운드 파일 동기화는 없습니다. 재시작 후 미완료 가져오기를 직접 재개하세요. 복원한 스페이스에서는 이전 가져오기의 원본을 다시 선택하고 확인해야 합니다.

## 작성과 저장

**새 자료**에서 독립 노트, 프로젝트, 레코드, 재사용 자산을 만듭니다. 노트가 프로젝트에 속할 필요는 없습니다. **상세 정보**에서 필드와 관계를 편집하면 같은 노트나 자산을 복제하지 않고 여러 프로젝트에서 참조할 수 있습니다.

직접 편집한 내용은 입력을 잠시 멈추면 바로 저장됩니다. **지금 저장**도 사용할 수 있습니다. 편집기 옆의 상태를 확인하세요.

- **저장됨**은 표시된 편집 내용이 현재 내용으로 저장됐다는 뜻입니다.
- **복구용 초안을 보관했습니다**는 초안을 별도로 보관했다는 뜻이며 본문 저장 완료와 구분됩니다.
- **저장되지 않음**이나 **저장 결과 확인 중…**이면 편집기를 열어 두고 제공된 재시도로 원래 요청의 결과를 확인하세요.

충돌 시 편집 내용과 더 최신의 저장 버전을 각각 보존합니다. 현재 원문을 확인한 뒤 계속할 방법을 결정하세요. 초안도 보관할 수 없다면 닫기 전에 **편집 내용 복사**로 본문을 따로 보존할 수 있습니다. 보관된 초안은 작업 이어가기에서 엽니다. 초안을 다시 여는 것만으로 정식 내용이 되지는 않습니다.

레코드는 텍스트, 유한한 숫자, 불리언, 날짜, 선택 값을 지원합니다. 미설정(`null`), 빈 텍스트, `0`, `false`는 서로 다릅니다. 필드 이름을 바꿔도 정체성은 유지되며 유형을 바꾸면 값은 미설정이 됩니다. 필드 정의를 재사용하면 본문이나 관계를 복사하지 않고 값이 미설정인 새 레코드를 만듭니다. 레코드 표는 같은 자료를 제한된 범위로 표시하며 선택한 기준 레코드의 필드를 열로 사용합니다.

## 프로젝트에 쌓인 자료와 출처 읽기

프로젝트 개요에는 목표 발췌, 이어서 작업할 참조, 직접 자산 참조와 페이지로 나눈 자료가 있습니다. **프로젝트 본문 편집**으로 전체 내용을 작성하고, 비어 있다면 **프로젝트 목표 편집**을 선택하세요. 개수는 로드된 자료나 기록된 참조를 나타냅니다. 필드와 이어서 작업할 링크는 필요에 맞게 사용할 수 있으며 정해진 일과를 요구하지 않습니다.

관계는 **현재 버전 따르기** 또는 **고정 버전**을 사용합니다. 출처를 나중에 편집해도 인용은 당시 저장된 버전을 유지합니다. 과거 프로젝트의 링크와 현재 프로젝트 자료는 별도로 표시되며 과거에 연결된 모든 자료의 스냅샷은 아닙니다.

출처 읽기에서 **현재 원문 편집**을 선택하면 같은 관리 객체의 현재 버전이 열립니다. 예를 들어 버전 1을 읽으며 현재 버전 2를 편집해 저장하면 같은 객체의 버전 3이 됩니다. 버전 1과 인용은 바뀌지 않습니다. 이미 저장하지 않은 편집이 있다면 원래 편집기에 기준 버전 및 충돌과 함께 남습니다. **읽기로 돌아가기**는 인용 버전과 이전 위치를 복원합니다. 현재 원문이 보관되거나 사용할 수 없어도 읽을 수 있는 이력은 남습니다. 이 작업은 외부 원본 파일이 아닌 관리 사본을 편집합니다.

**저장된 컨텍스트 복사**는 이 항목에 저장된 제목, 본문, 필드, 관계, 버전 정보와 스페이스 정보를 복사합니다. 본문 일부를 선택하면 전체 본문 대신 선택한 부분을 포함하며, 연결된 문서의 본문은 포함하지 않습니다. 여러 버전 참조와 작업 설명을 함께 전달하려면 아래의 맥락 준비 기능을 사용하세요.

## 에이전트에게 줄 맥락 준비하기

저장된 문서나 출처 읽기에서 **컨텍스트 준비**를 선택합니다.

1. 필요한 경우 Unicode 코드 포인트 기준 최대 1,000자의 짧은 작업 설명을 씁니다.
2. **중복되지 않는 저장 버전 참조를 최대 20개** 선택합니다. 처음에는 시작 자료만 선택됩니다. 후보는 그 버전의 직접 링크와, 시작 자료가 프로젝트인 경우 현재 활성 프로젝트 자료입니다. 각 그룹에서 더 불러올 수 있습니다.
3. **설명과 참조 확인**을 열어 보이는 내용을 확인하고 **설명과 참조 복사**를 사용합니다.

설명에는 작업과 고정 참조가 포함됩니다. 시작 프로젝트를 선택한 경우 최대 280자의 목표 발췌도 포함할 수 있습니다. 선택을 해제하면 해당 제목과 발췌도 빠집니다. 연결된 문서의 본문을 재귀적으로 포함하지 않습니다. 사용할 수 없는 선택 버전은 재시도하거나 제외해야 하며 새 버전으로 대체되지 않습니다.

복사 완료는 텍스트가 클립보드에 들어갔다는 뜻입니다. 접근 권한을 만들거나 에이전트 수신을 확인하지는 않습니다. 준비 내용은 스페이스를 열어 둔 동안 메모리에 남고 설정이나 가져오기를 다녀와도 유지됩니다. 저장 문서나 재시작 후 복구할 수 있는 초안은 아닙니다.

## 접근 권한을 만들고 에이전트 연결하기

맥락 준비에서 **에이전트 접근 설정**을 선택하거나 **설정**에서 같은 항목을 엽니다.

1. 권한에 이름을 붙이고 선택한 객체 또는 전체 스페이스를 지정한 뒤 읽기와 제안 권한을 고릅니다.
2. 첫 페이지 밖의 준비 자료를 포함해 선택을 확인합니다. 기존 양식의 선택은 유지되며 **선택한 자료 사용**으로 직접 교체합니다.
3. **접근 권한 만들기**를 누르고 Codex 구성 또는 stdio 실행 JSON을 복사합니다. 에이전트를 사용하는 앱의 MCP 설정에 추가하고 다시 연결한 뒤 설명을 에이전트에 전달합니다. [프로토콜 안내](../AGENT_PROTOCOL.md)에는 CLI 사용법도 있습니다.

설명은 특정 버전을 고정하지만 객체 접근 권한은 **이후 버전도 포함한** 읽기 가능한 버전을 대상으로 합니다. 새 링크나 프로젝트 자료는 고정 선택에 추가되지 않습니다. 새 노트·레코드 제안에는 읽기와 제안이 허용된 전체 스페이스 권한에 별도 생성 권한이 필요합니다. 특정 객체 권한으로는 새 객체를 만들 수 없습니다. 에이전트에 직접 저장이나 제안 적용 권한이 주어지지 않습니다.

구성의 토큰은 발급 시 한 번만 표시되고 AgentSpace에는 해시만 저장됩니다. 표시되는 동안 복사하세요. 잃어버리면 해당 권한을 취소하고 새로 만듭니다. 접근 작업 결과가 불확실하면 양식이 잠기며 원래 요청을 재시도해 확인합니다. 같은 스페이스를 연 채 설정을 다녀와도 이미 받은 일회성 구성은 유지됩니다.

에이전트는 권한 내에서 자료를 발견·필터링·검색하고, 범위가 제한된 관계 탐색과 특정 버전 읽기를 조합할 수 있습니다. 검색은 범위와 제한을 표시하며 의미상 완전한 검색을 보장하지 않습니다. “준비된 컨텍스트”는 도구 결과를 위해 구성한 참조와 범위를 기록합니다. 호스트 수신, 모델의 이해, 작업 완료를 증명하지 않습니다.

**상세 정보 → 에이전트 제안 권한**에서 에이전트가 변경을 제안할 수 있는 부분을 선택하고 **제안 권한 저장**을 누르세요. 내용을 편집해도 기존 권한은 유지됩니다. 모든 제안은 직접 검토한 뒤 적용해야 합니다.

## 제안 검토와 변경 확인

**검토 → 처리 대기**에서 제안을 엽니다.

1. 목적, 이유, 대상, 기준 버전과 전체 차이를 읽습니다. 출처는 인용 버전으로 열립니다. 돌아오면 제안 선택과 읽던 위치가 유지됩니다.
2. 수정 제안은 **변경 제안 적용**, 새 객체 제안은 **노트 만들기** 또는 **레코드 만들기**로 반영합니다. **변경 제안 거절**은 정식 내용을 바꾸지 않습니다.
3. 새 객체 제안에서 **새 자료 초안**을 선택하면 같은 유형의 초안을 시작합니다. 수정 제안은 현재 객체를 직접 편집합니다. 원래 제안은 따로 남습니다.

읽는 것만으로 제안이 처리되지는 않습니다. 읽음·읽지 않음, 대기·적용·거절·충돌, 사람의 지식 검토 상태는 서로 다릅니다. 현재 저장된 버전이 제안의 기준 버전과 다르면 적용할 수 없으며 제안과 현재 내용을 모두 보존합니다. **제안된 내용 복사** 후 현재 객체를 직접 편집하거나 에이전트에게 새 제안을 요청할 수 있습니다. 해당 에이전트의 접근 권한을 취소한 뒤에도 기존 제안을 거절할 수 있습니다.

**검토 → 처리됨**에서 적용하거나 거절한 제안을 확인합니다. **적용 당시 버전 읽기**는 적용 시 저장된 결과를 열고 현재 원문은 별도로 엽니다. 거절된 제안도 이유, 차이, 출처를 유지합니다.

**활동 → 실제 변경**에는 저장과 제안 결정이 시각·실행자와 함께 남으며 당시 버전이나 원래 제안으로 이동할 수 있습니다. 다른 허가된 에이전트도 원래 채팅 없이 적용 설명과 출처 참조를 추적할 수 있습니다. 결과를 읽을 수 있다고 출처 접근 권한도 생기는 것은 아닙니다.

**기록**에서 **실행 취소 미리 보기**로 확인한 뒤 되돌립니다. 이후 편집이 있으면 덮어쓰기를 거부합니다. 이전 버전을 읽거나 그 버전으로 새 노트를 만들 수도 있습니다.

## 검토한 지식 표시하기

**상세 정보 → 버전 검토**에서 현재 저장된 버전과 사람이 마지막으로 검토한 버전을 비교합니다. 저장된 현재 버전을 확인한 뒤 **검토됨으로 표시**를 선택하세요. 저장하지 않은 편집은 별도로 유지됩니다.

라이브러리의 **검토 상태**에서 **검토 전**, **현재 버전 검토됨**, **검토 후 변경됨**을 찾습니다. 검토 전은 중립적인 정보입니다. 가져오기, 저장, 읽기, 제안 적용으로 지식이 자동 검토되지는 않습니다. 표시는 사람이 해당 버전을 검토했다는 기록이며 사실 인증이나 자동 지식 관리는 아닙니다.

## 자료 보관과 외부 자산 다시 연결하기

**상세 정보 → 자료 보관**은 정체성과 이력을 유지하면서 활성 보기에서 제외합니다. **보관함에서 복원**으로 다시 활성화할 수 있습니다. 프로젝트를 보관해도 관련 노트와 공유 자산을 함께 보관하거나 삭제하지 않습니다.

외부 자산이 이동하면 **외부 자산 위치 선택**에서 이전 위치와 새 위치를 확인합니다. 정체성과 이력은 유지되며 외부 파일 자체는 이동하지 않습니다. 일반 실행 취소로 위치 변경을 되돌릴 수는 없습니다. 이전 위치로 돌아가려면 그 위치를 직접 선택하세요.

## 백업, 내보내기와 복원

스페이스 메뉴에서 **백업, 내보내기 및 복원**을 엽니다.

| 선택            | 용도                         | 포함                                                                            |
| --------------- | ---------------------------- | ------------------------------------------------------------------------------- |
| 전체 백업       | 이력과 함께 스페이스 복원    | 일관된 DB, 보존된 버전, 제안, 작업 이력, 초안과 가져오기 진행 상태              |
| 읽기용 내보내기 | 다른 도구에서 현재 내용 읽기 | 보관된 항목을 포함한 현재 확정 내용, 유형이 지정된 필드, 관계와 출처 메타데이터 |

읽기용 내보내기는 이전 본문, 제안, 복구용 초안을 제외하므로 전체 이력 복원에 사용할 수 없습니다. 과거 인용이 내보내기에 없는 본문을 가리킬 수도 있습니다. 두 방식 모두 외부 파일이나 저장소의 실제 내용을 복사하지 않으며 원본 경로 같은 개인 메타데이터를 포함할 수 있습니다.

**완료 및 검증됨**을 기다린 뒤 성공을 확인하세요. 응답을 잃으면 결과는 알 수 없는 상태이므로 원래 작업을 확인하거나 재시도합니다. 완료된 복원본을 열 수 없다면 열기만 따로 재시도하세요. 검증된 복원 결과가 취소된 것은 아닙니다.

백업은 **새 대상 위치**에 복원합니다. 복원본에는 새 인스턴스 ID가 부여되며, 복사된 기존 에이전트 접근 권한은 비활성화됩니다. 원래 스페이스와 그 접근 권한은 그대로 유지됩니다. 복원본에 에이전트를 연결하려면 새 접근 권한을 발급해 다시 연결하세요. 복구 기능에서 다른 설치의 초안을 찾아 선택한 내용을 새 로컬 초안으로 복사할 수 있으며 원래 초안은 그대로 남습니다.

## 개인정보, 제한과 추가 안내

AgentSpace 자체는 로컬 데이터를 암호화하지 않습니다. 운영체제 기능으로 스페이스와 사본을 보호하세요. 연결된 에이전트는 허용된 내용을 받고 호스트 설정에 따라 모델 제공자에게 보낼 수 있습니다. 로컬 저장이 이 전송을 막지는 않습니다. 권한 취소는 이후 도구 접근을 차단하지만 이미 공유한 자료는 회수하지 못합니다.

관리 객체의 전체 내용은 1 MiB, 이력을 포함한 DB는 512 MiB까지입니다. 가져오기에는 깊이 12, 방문 항목 1,000개, 선택한 텍스트 50 MiB 등의 제한이 있습니다. 맥락 도구도 결과 수와 바이트 제한이 있습니다. 한도에 도달한 스페이스도 쓸 수 있는 위치로 백업·내보내기가 가능합니다.

[제품 범위](../PRD.md), [로컬 데이터와 복구](../LOCAL_DATA.md), [신뢰 경계](../SECURITY.md)를 참고하세요. 현재 대상은 macOS Apple Silicon입니다. [데스크톱 설정](../DESKTOP.md)과 [검증](../TESTING.md)에 서명, 플랫폼과 입력기 검증 범위를 정리했습니다.

## Persistence and recovery boundaries

Real file-backed Core tests cover creation/reopen, immutable old revisions, typed multilingual data, strict schemas, grants and revocation, reserved creation IDs, human-only acceptance, exact payload/status/base guards, original receipts and conditional undo. Human drafts have monotonic generations and cannot be resurrected by a late save after discard. Activity and draft polling do not manufacture accepted changes or invalidate content query pages.

Independent compiled Core processes race on the same SQLite file. An old-base race has one winner; canonical same-key retries recover one fixed result. SIGKILL immediately before COMMIT leaves no accepted head/change/receipt/search text. A writer exiting after COMMIT without replying is recovered by another process under the original key. Real SQLite capacity exhaustion returns `LIMIT_EXCEEDED` without partial authority. These are not host power-loss or disk-full experiments.

Import journal, item, revision, receipt and search publication commit together. Tests cover pause/restart/resume, per-item outcomes, competing runs, source reauthorization and unchanged BOM/CRLF/Unicode originals. A duplicate source/version returns its original object and pin, preserving later human content and relationships. Import progress pagination binds a revision: a concurrent update restarts the page set, and continuing churn fails with a retryable result rather than mixing states. Both the incoherent-pagination and stale-backup regressions were reproduced before correction and passed afterward.

Backup/export tests include an online concurrent writer, an actually capacity-full source and interruption after snapshot acquisition. Restore verifies the reviewed backup's exact bytes and metadata before publishing. Separate real-process regressions replace the reviewed source, reusable scratch or acquired staging with another healthy backup of the same space/instance; all are refused. Retrying the original operation with the original backup succeeds, and complete replay cannot overwrite later human edits. Closed backups use bounded byte-copy acquisition; active-space snapshots use SQLite's online backup. Node-created format-2 backup restoration also passes under Electron's different bundled SQLite version.

## Bounded performance observation

A local format-2 baseline created 1,000 synthetic multilingual notes and 30 projects containing 4.24 MB of authored bodies in 1.32 seconds. Thirty project-filtered literal queries returning 20 summaries measured p50 4.51 ms and p95 5.58 ms under ordinary background load. A 20-item result used 5,976 UTF-8 Result bytes and explicitly reported truncation; a fixed body page obeyed a 2,048-byte budget. This is one Node 22.22.3 / SQLite 3.51.3 development-machine observation, not a workload SLA, semantic-recall result or maximum-capacity benchmark.

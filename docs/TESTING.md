# Test strategy and evidence

Status: phase 2, 2026-11-22. Runtime probes and contract checks have run; **no application acceptance scenario is complete**. Test counts are not product guarantees. Product tests trace to SC-01–SC-09 and AS-01–AS-15 in [PRD.md](PRD.md). Failure races are engineering risks, not invented user stories. Temporary probe databases, output and scripts stay outside public source control; the tables below summarize their reproducible intent and limits.

| Five-language search      | Ten fixture queries in each runtime: English, one/two/three-character Chinese, short Japanese, short/long Korean, uppercase accented Spanish and decomposed café. Source text stayed unchanged.                                                                                                                                                                                    | Synonyms, accent-insensitive matching, broad language quality, large-space latency or product search implementation            |

Concurrent same-key requests produced one change/receipt and the same result. A process committed and exited before replying; another process recovered the original receipt. | Contracts                 | Six tests cover forbidden fields/tools, create/update and target-expectation combinations, multilingual authored field labels/types, relation modes, agent read budgets/continuation and five locale identifiers.                                                                                                                                                                                                                                                                         | Runtime core enforcement, full translations or UI usability                                                                    |

The SQLite checks used actual file connections and the online API, not an in-memory-only connection or copied live database file. The mixed-runtime fixture deliberately contains only a tiny entity/receipt/change schema. It validates an engine strategy; it is not a disguised implementation or PRD acceptance test.

Current public commands are `npm ci`, `npm run check` and `npm run format:check`. Check output and dependency audit are reported with the phase handoff. There is no application build, package or native E2E result yet.

## P0 checks that block delivery

| Boundary                          | Failure exercised and required outcome                                                                                                                                                                                                                                                                                                                                                              |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Old proposal vs human work        | Agent reads r1 and proposes; human saves r2. Acceptance preserves r2 and the candidate, reports conflict and allows inspecting both. Repeat while a dirty editor buffer exists. Rejection must still work after later edits/conflict or originating-grant revocation, with candidate/status guards only.                                                                                            |
| Response lost / stable namespace  | Kill or disconnect the adapter after commit before reply; retry same key after process restart. Exactly one revision/change, original receipt. Reuse the key for a different payload/command and fail without a second change.                                                                                                                                                                      |
| New-object proposals              | Whole-space propose grant suggests a document/record with no base. Before acceptance there is no current target. Reject object-scoped creation, project/asset creation and reserved/existing-ID collisions. Same-key replay returns the same candidate; acceptance creates r1 once.                                                                                                                 |
| Reviewed proposal identity        | Open proposal P/hash A/status v1. Attempt replacement/rebase or a second review. Human command with stale hash/status/version must fail; rebase has a new proposal ID. “Use as draft” retains the agent original.                                                                                                                                                                                   |
| Conditional undo and ABA          | Create r1(A), r2(B), r3(A). Undo r2 must not pass by comparing text; later revisions survive. Also test simple allowed undo, duplicate retries and an old version opened as a new draft.                                                                                                                                                                                                            |
| External refresh and dirty buffer | Separate real MCP/CLI process writes/proposes while Electron is open. Clean views catch the sequence change; dirty/composing buffers remain byte-for-byte intact, stale saves conflict, and wrong-space/out-of-order responses are ignored. Read-only agent calls advance independent activity IDs and appear without an authority-sequence change; UI polling does not generate agent-call events. |
| Draft lifecycle                   | Recovery write success is not shown as accepted save. Simulate save/busy/storage failure; navigate and close; reopen draft with its old base. Do not overwrite an external head during recovery. Preserve latest generation during serialized autosave.                                                                                                                                             |
| Backup and restore                | Concurrent writer during online backup; restore to unused directory; verify IDs, all retained pins/digests/types/receipts and integrity. Reject missing references/newer schema/corruption/occupied destination. Restored grants start disabled; incomplete output is not opened as a valid space.                                                                                                  |
| Bounded reads and relation modes  | Read a long mixed-language body in small budgets; concatenate pages from a fixed pin without lost/split characters after the head changes. Check measured JSON byte budget, section/range/truncation, oversized-field errors and revoked-scope continuation. Project rename resolves current identity while evidence remains at its pinned old revision.                                            |
| MCP scope and identity            | No actor/path/SQL/shell/human-review inputs; deny outside-scope reads/proposals, sources, relation labels, counts/snippets and receipts. Revoke a grant while connected; next call fails. Stable grant ID survives connection restarts.                                                                                                                                                             |
| Renderer boundary                 | Actual Electron sandbox/isolation/nodeIntegration settings, top-level sender validation, no raw IPC or Node/db/fs in renderer, navigation/new-window denial, safe Markdown and unsafe-link/remote-image payloads. Check code imports and runtime behavior.                                                                                                                                          |
| Five-language editing/review      | Dictionary parity and no fallback keys; all five locales create/edit/save/review/conflict/restore. Locale switch preserves content. Native CJK composition, keyboard focus/source return, long Spanish labels, 980px window and 125–200% zoom remain usable.                                                                                                                                        |
| Portable package                  | Move the built app to a path with spaces, start from Finder or equivalent clean environment, create/open space outside repository, run the core flow and reconnect an external adapter. No source-tree paths, developer binaries or system Node requirement for the desktop.                                                                                                                        |

Use unit/schema tests for pure boundary shapes, file-backed integration for authority, spawned processes for concurrency, the official SDK for transport, and actual Electron automation for native behavior. Mocked transports and browser-only pages can assist development but cannot satisfy the corresponding boundary. Capture real screenshots after interaction review; a screenshot alone does not prove persistence or security.

## Broader checks and limits

Phase 4 adds query/expansion byte and node limits, cursor staleness after authority/grant changes, pinned missing-source behavior, original import preservation, typed-field definition protection and export round-trips. Phase 5 adds realistic data/latency checks, interrupted saves/backups, keyboard/focus and accessibility review, clean-install CI, packaging and regression fixes. Test induced failures with isolated synthetic spaces; do not use personal source folders as fixtures.

No power-cut, full-disk, filesystem-corruption recovery, large-library performance, Windows/Linux product, app signing/notarization, named external model host or arbitrary native-file synchronization has been verified. Record actual limits with each result. Updating runtime/driver/SDK versions reopens the relevant compatibility checks; a lockfile is a dependency pin, not proof that an application works.
